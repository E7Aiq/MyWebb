# خطّ البناء وتهيئة الظهور — alzobaidi.me

هذا الملف يشرح كيف يتحوّل ما تكتبه في Notion إلى صفحات يراها محرّك البحث،
وما الذي يجب أن تفعله أنت — ولا شيء غيره — كي يبقى ذلك صحيحاً.

---

## ١. الصورة الكاملة في ثلاث خطوات

```
Notion ──► .github/scripts/fetch-*.js ──► data/*.json ──► .github/scripts/build-site.js ──► صفحات HTML
   (١)              (٢)                       (٣)                    (٤)                        (٥)
```

| # | ما هو | من يشغّله | ماذا يلمس |
|---|---|---|---|
| ١ | قاعدتا Notion (المقالات، المشاريع) | أنت | المحتوى |
| ٢ | الجالبان — كما كانا، **لم يُمسّا** | GitHub Actions يومياً ٣ صباحاً UTC | يكتبان `data/*.json` وينزّلان الصور |
| ٣ | `data/articles.json` و`data/projects.json` | — | مصدر الحقيقة للمحتوى |
| ٤ | **البناء** — الطبقة الجديدة | نفس التشغيلة، بعد الجلب مباشرة | يقرأ `data/` ويكتب الصفحات |
| ٥ | صفحات ساكنة كاملة | GitHub Pages | ما يراه الزائر والزاحف |

**القاعدة الحاكمة:** طبقة البناء تقرأ `data/` ولا تكتب فيه أبداً (عدا سجلّ
المعرّفات، §٦). فإن تعطّلت، بقيت البيانات سليمة وأمكن إعادة البناء وحده.

---

## ٢. ما ينتجه البناء بالضبط

`node .github/scripts/build-site.js` يكتب:

| المسار | ما هو |
|---|---|
| `articles/<معرّف>/index.html` | صفحة المقال كاملةً في الترميز |
| `projects/<معرّف>/index.html` | صفحة المشروع كاملةً في الترميز |
| `articles/index.html` · `projects/index.html` | الفهرسان، مصيَّران مسبقاً |
| `topics/index.html` · `topics/<موضوع>/index.html` | فهرس الموضوعات وصفحة لكل موضوع |
| `assets/og/*.jpg` | بطاقة مشاركة ١٢٠٠×٦٣٠ لكل صفحة |
| `sitemap.xml` · `feed.xml` · `robots.txt` | بنية الزحف (الخريطة تنقسم إلى `sitemap-N.xml` وفهرسٍ يجمعها متى تجاوزت ٥٠٠٠ رابط) |
| `articles.html` · `projects.html` · `article.html` · `project-details.html` | جسور تحويل للمسارات القديمة |
| `a/<معرّف>/` · `p/<معرّف>/` | روابط قصيرة لاتينية (§٧) |
| مناطق مُدارة داخل `index.html` | الرأس + بطاقتا المختارات |
| `data/slugs.json` | سجلّ المعرّفات (§٦) |

ثم **يكنس**: أي صفحة مولَّدة لم يعد لها مصدر في `data/` تُحذف. إلغاء نشر مقال
في Notion يزيل صفحته فعلاً بدل أن يتركها معلّقة على الخادم.

## ٣. أيّ حقل في Notion يغذّي أيّ وسم

هذا هو الجدول الذي يهمّك عملياً.

| حقل Notion | النوع | يذهب إلى | إن تُرك فارغاً |
|---|---|---|---|
| **Title** (العنوان) | Title | `<title>` · `<h1>` · `og:title` · `twitter:title` · `headline` في JSON-LD · **مسار الصفحة** | لا صفحة (يُسمّى «Untitled») |
| **Description** (المقالات) | Rich text | `<meta name="description">` · `og:description` | **يُشتقّ من أول فقرة نثر في المتن** — يعمل، لكن أنت أدرى بما يجذب النقرة |
| **Summary** (المشاريع) | Rich text | نفس ما سبق + نصّ البطاقة في الفهرس | كما أعلاه، وتبقى البطاقة في الفهرس بلا سطر وصف |
| **Date** | Date | `article:published_time` · `datePublished` · التاريخ المعروض · `lastmod` في الخريطة · ترتيب الفهرس | لا تاريخ معروض، ويهبط العنصر إلى آخر الترتيب |
| **Tags** (المقالات) | Multi-select | صفحات الموضوعات · الروابط المرتبطة · `article:tag` · `keywords` | **المقال لا يظهر في أي صفحة موضوع ولا يرتبط بشيء** |
| **Category** (المقالات) | Select | يظهر في صفّ الميتا + يُعامَل موضوعاً | لا شيء يظهر |
| **Categories** (المشاريع) | Multi-select | كما Tags + أزرار الفلترة في الفهرس | كما أعلاه |
| **ReadTime** | Number | «٣ دقائق قراءة» · `timeRequired` | يُقدَّر آلياً من عدد الكلمات |
| **Featured** | Checkbox | يرفع المقال إلى صدارة الفهرس | ترتيب زمني عادي |
| **Published** | Checkbox | **الجالب لا يرى إلا المؤشَّر** | لا يُنشَر |
| **غلاف الصفحة** (Cover) | صورة Notion | `og:image` (يُقصّ ١٢٠٠×٦٣٠ JPEG) + غلاف الصفحة | تُرسَم بطاقة من العنوان بخطّ الموقع — **ولا تُستعمل صورتك الشخصية أبداً لمقال** |
| **تعليق تحت صورة في المتن** | Caption | `alt` الصورة + `<figcaption>` | تُعلَن الصورة زخرفية `alt=""` ويُنبّه البناء بعددها |

> **لماذا يُشتقّ الوصف ولا يُختلَق:** قاعدة هذا الخطّ أن لا يكتب نصّاً لم
> تكتبه أنت. فإن غاب الوصف، يُقتطع من نثر المقال نفسه (١٥٠–١٦٠ محرفاً،
> يُقطع عند حدّ جملة). صحيح دائماً، لكنه ليس بجودة سطرٍ تكتبه أنت لِتُنقَر.

## ٤. ماذا تفعل عند إضافة مقال جديد

1. اكتب المقال في Notion كالعادة.
2. املأ **Tags** — هذا أهم حقل بعد العنوان. بلا وسم، لا يدخل المقال أي صفحة
   موضوع ولا يرتبط بأي مشروع، فيخسر أكثر ما يجلبه الذيل الطويل من الزيارات.
3. املأ **Description** بجملة أو جملتين (١٥٠–١٦٠ محرفاً). هذا ما يقرؤه الناس
   في نتيجة البحث.
4. ضع **غلافاً** للصفحة إن أمكن — يصير بطاقة المشاركة.
5. اكتب **تعليقاً تحت كل صورة** في المتن — يصير النصّ البديل.
6. أشِّر **Published**.
7. لا شيء بعدها. التشغيلة اليومية تجلب وتبني وتودِع، فتُولَد الصفحة ومسارها
   وبطاقتها ومدخلها في الخريطة والتغذية وروابطها الداخلية بلا لمسة منك.

**للتشغيل الفوري بدل الانتظار:** GitHub → Actions → «Update Articles from
Notion» → Run workflow.

## ٥. التشغيل محلياً

```bash
npm install     # مرّة واحدة — تبعيات بناء لا تُشحن إلى المتصفّح
npm run seo     # يبني ثم يفحص
npm run build   # البناء وحده
npm run check   # الفحص وحده
npm run serve   # خادم محلي على 5173
```

`npm run check` **يخرج بحالة فشل** إن وجد:
صفحة بلا عنوان أو وصف أو رابط معياري أو بطاقة مشاركة · عنوانين أو وصفين
متطابقين · رابطاً داخلياً مكسوراً · صفحة يتيمة لا يبلغها الزاحف من الرئيسية ·
كتلة JSON-LD لا تُحلَّل أو ينقصها حقل واجب · صفحة خارج خريطة الموقع ·
باعث تحديث غير موحّد · صورة بلا `alt`.

وهو موصول بخطوة البناء في كلا مسارَي Notion، فلا تصل صفحة معطوبة إلى النشر.

## ٦. المسارات وسجلّ المعرّفات

المعرّف يتبع خطّ العنوان: عربيّ للعنوان العربي، لاتينيّ للاتيني. لا نقحرة —
«aldhka-alastnay» ليست كلمةً في أي لغة، فتخسر معنى العنوان ولا تكسب شيئاً.

`data/slugs.json` سجلّ يحفظ **أول معرّف أُعطي لكل عنصر**. لماذا: لو غيّرت
عنوان مقال في Notion، لتغيّر معرّفه ولانكسر رابطٌ ربما شاركه أحد. السجلّ
يمنع ذلك: المعرّف الأول يبقى مسار الصفحة، والمعرّف القديم — إن تغيّر — يُسجَّل
في `aliases` ويُكتب له **جسر تحويل تلقائي**.

> **لا تحرّر `data/slugs.json` يدوياً.** إن أردت تغيير مسار صفحة عمداً: احذف
> مدخلها من الملف وأعد البناء؛ سيُشتقّ معرّف جديد من العنوان الحالي، ويُكتب
> للقديم جسر.

**كتابة السجلّ دمجٌ لا استبدال.** يُعاد قراءة الملف لحظة الكتابة لا لحظة بدء
البناء، فمدخلٌ كتبته تشغيلة أخرى في الأثناء لا يُمحى، والأسماء المهجورة
تُجمع من الجهتين. **ولا يُحذف مدخل أبداً كأثر جانبي** — حذفه يكسر رابطاً
منشوراً. راجع §10 «تسابق المسارين».

### الجسور تتراكم — وهذا مقصود

كل تغيير عنوان في Notion يضيف اسماً مهجوراً إلى `aliases`، ولكل اسم مهجور
صفحة جسر دائمة تحت `articles/<الاسم-القديم>/` أو `projects/…`.

**لا تُحذف آلياً، ولن تُحذف.** الجسر موجود لأن أحداً قد يكون شارك ذلك
الرابط، ولا سبيل لمعرفة ذلك. حذفه يحوّل الرابط المنشور إلى ٤٠٤، وهذا أسوأ
من صفحة جسرٍ وزنها كيلوبايت.

الكلفة ضئيلة: الجسر ملف صغير، `noindex, follow`، خارج خريطة الموقع، ولا يظهر
في أي فهرس. عشرة تغييرات عنوان في السنة تعني عشرة ملفات.

**راجعها مرّة في السنة:** المفتاح `aliases` في `data/slugs.json` يعدّها.

```bash
node -e "const l=require('./data/slugs.json');
  for (const [id,r] of Object.entries(l))
    if (r.aliases.length) console.log(r.kind, r.slug, '←', r.aliases.join(' , '));"
```

**لحذف جسر عمداً:** احذف الاسم من مصفوفة `aliases` في `data/slugs.json` ثم
`npm run seo` — يكنس البناء صفحته. **وما ينكسر:** كل رابط منشور بذلك
المسار يصير ٤٠٤ فوراً. لا تفعلها إلا لاسمٍ تعرف يقيناً أنه لم يُنشر — عمرُه
أقلّ من ساعة مثلاً، أو تغيير عنوان قبل أول مزامنة.

## ٧. الروابط القصيرة

لكل مقال ومشروع رابط قصير لاتينيّ إلى جانب مساره النظيف:

```
https://alzobaidi.me/a/d7a78374/     ← مقال      (٣٢ محرفاً)
```

حين لا تريد لصق رابطٍ عربيّ مرمَّزٍ بـ٢٢٢ محرفاً في رسالة — التفصيل في
`SEO-REPORT.md` §٢.

## ٨. المناطق المُدارة في `index.html` و`404.html`

الصفحتان مكتوبتان بيدك وتبقيان كذلك. البناء لا يعيد كتابتهما — يستبدل ما بين
علامات فقط.

| المنطقة | في | ما تحويه |
|---|---|---|
| `seo:assets` | الاثنتان | سكربت الانتقال، تحميل الخطوط المسبق، ووسوم الأنماط — بباعث التحديث |
| `seo:scripts` | الاثنتان | وسوم السكربتات في آخر الجسد — بباعث التحديث |
| `seo:head` | `index.html` | العنوان، الوصف، canonical، Open Graph، البيانات المنظّمة |
| `seo:featured-projects` | `index.html` | بطاقة أحدث مشروع |
| `seo:featured-articles` | `index.html` | بطاقة أحدث مقال |

```html
<!-- seo:assets:begin -->
    … يكتبها البناء …
<!-- seo:assets:end -->
```

**ما بين العلامتين يُمحى في كل بناء.** لتغيير عنوان الصفحة الرئيسية أو وصفها
أو باعث التحديث: `data/site.json`. ولإضافة ملف CSS أو JS إلى صفحة يدوية:
`MANAGED_ASSETS` في `.github/scripts/build-site.js` — لا الملف نفسه.

**ما ليس مُداراً في تينك الصفحتين** (ويبقى بيدك وحدك): `<meta charset>`
و`viewport` والسكربت السطري لبوابة الكشف، وقواعد التهيئة المسبقة
(Speculation Rules)، ووسوم الأيقونة، وكل جسد الصفحة خارج منطقتَي المختارات.
ضعْ وسم تحقّق Search Console **خارج** العلامات — راجع `SEO-REPORT.md` §4
المهمّة ٣.

**البناء يتوقّف برسالة صريحة** إن اختفت علامة، أو تكرّرت، أو جاءت `end` قبل
`begin` — الكتابة في موضع مُخمَّن أسوأ من التوقّف.

## ٩. `data/site.json` — المصدر الوحيد

كل عنوان ووصف ورابط ثابت في الموقع يُقرأ من هنا: اسم الموقع، الأصل
(`origin`)، باعث التحديث، وصف الرئيسية، تعريف القسمين، روابط `sameAs`،
والموضعة.

**باعث التحديث (`cacheBuster`):** أي تعديل على CSS أو JS يوجب رفعه
(`r31` ← `r32`)، وإلّا بقي الزائر العائد على النسخة المخبوءة.

**يُرفع في هذا الملف وحده.** كل صفحة تأخذه من هنا: المولَّدة عبر مولّد
الرأس، و`index.html` و`404.html` عبر منطقتَي `seo:assets` و`seo:scripts`
المُدارتين (§8). لا تحرّر وسم أصلٍ في أيّ ملف HTML — يُمحى في البناء التالي.

```bash
# ارفع cacheBuster في data/site.json، ثم:
npm run seo
```

فحص التباين في `check-seo.js` باقٍ كما هو: يفشل البناء إن حملت صفحتان قيمتين
مختلفتين، أو إن خالفت الصفحات ما في `site.json`. لم يعد يُطلق في الاستعمال
العادي — صار حارساً على منطقة تالفة لا خطوةً على عاتقك.

**بطاقة الرئيسية (`home.og_image`):** `null` ⇒ تُرسَم من الاسم والدور بخطّ
الموقع. لاستعمال صورة خاصّة ضع مسارها (١٢٠٠×٦٣٠، أو ما يُقصّ إليه بلا قطع
الوجه). الصورة الشخصية الحالية ٦٤٠×٨٥٧ عمودية وقصّها يقطع الرأس، ولذلك
البطاقة المرسومة هي الافتراض. القاعدة الثابتة: **لا صورة شخصية بطاقةً لمقال.**

**الموضعة:** الحقلان `search_role_ar` و`hero_role_ar` مختلفان اليوم عمداً
(«محلل بيانات» مقابل «مطوّر حلول البيانات والذكاء الاصطناعي»). البناء يُبقي
كلاًّ في مكانه كما هو، ويطبع تحذيراً. لتوحيدهما اجعل القيمتين متطابقتين.

## ١٠. تسابق المسارين على الملفّات المولَّدة

مساران في GitHub Actions يكتبان **الملفّات المولَّدة نفسها**: `sitemap.xml`
و`feed.xml` و`data/slugs.json` و`assets/og/*` وأشجار `articles/` و`projects/`
و`topics/` والجسور. كلّ منهما يبني الموقع كاملاً لأن البناء يقرأ ملفَّي
البيانات معاً.

ثلاثة خطوط دفاع، مرتّبة:

1. **الإزاحة الزمنية.** المقالات `0 3 * * *`، والمشاريع `30 3 * * *`. نصف
   ساعة تكفي لأي تشغيلة عادية (دقائق معدودة). هذا هو الحاجز الحقيقي.
2. **دمج السجلّ.** `data/slugs.json` يُعاد قراءته لحظة الكتابة ويُدمَج، فلا
   يُمحى مدخل كتبه الآخر (§6).
3. **`git pull --rebase --autostash` قبل الدفع.** يمنع فشل الدفع
   بـ`non-fast-forward`.

> **إن أضفت مساراً ثالثاً لاحقاً** (قاعدة Notion جديدة مثلاً): أعطه فتحة
> زمنية خاصّة به — `0 4 * * *` — ولا تجعله يتقاطع مع الاثنين. وإن احتجت
> تشغيلاً يدوياً (`Run workflow`) بينما مسارٌ آخر يعمل، انتظر انتهاءه؛
> الإزاحة لا تحمي من تشغيل يدويّ في التوقيت الخطأ.

## ١١. التراجع — حين يُنشَر شيء معطوب

هذه أهم صفحة في الملف حين تسوء الأمور. كل حالة: **العرَض ← الأمر ← كيف
تتأكّد**.

### أ. نشرتُ ودمجتُ، والموقع معطوب

**العرَض:** الموقع الحيّ خطأ بعد دمج فرع.

```bash
git checkout main
git log --oneline -5                 # اعرف رقم إيداع الدمج
git revert -m 1 <رقم-إيداع-الدمج>
git push
```

`-m 1` يعني «ارجع إلى الأب الأول» — أي حال `main` قبل الدمج. بدونها يرفض git
عكس إيداع دمج.

**كيف تتأكّد** (بعد ٢–٣ دقائق لبناء Pages):

```bash
curl -s -o /dev/null -w "%{http_code}\n" "https://alzobaidi.me/?cb=$RANDOM"
```

يجب أن يعطي `200`. ثم تأكّد أن المحتوى القديم عاد فعلاً:

```bash
curl -s "https://alzobaidi.me/?cb=$RANDOM" | grep -c "hero-title"
```

يجب أن يعطي `1`. (معامل `cb` عشوائي يتخطّى خبيئة CDN — بدونه قد ترى نسخة
قديمة وتظنّ أن التراجع لم يصل.)

### ب. مناطق `index.html` المُدارة تلفت

**العرَض:** البناء يتوقّف بـ«علامة المنطقة المُدارة … مفقودة/مكرّرة»، أو
الرئيسية تظهر بلا أنماط بعد بناء.

```bash
git checkout main -- index.html 404.html    # أعد الصفحتين اليدويتين من الفرع السليم
npm run seo                                  # أعد ملء المناطق
```

إن كان `main` نفسه هو التالف، عُدْ إلى آخر إيداع سليم:

```bash
git log --oneline -- index.html
git checkout <رقم-الإيداع-السليم> -- index.html
npm run seo
```

**كيف تتأكّد:**

```bash
grep -c "seo:assets:begin\|seo:assets:end\|seo:head:begin\|seo:head:end" index.html
```

يجب أن يعطي `4`. و`npm run check` يمرّ بلا أخطاء.

### ج. الصفحات المولَّدة و`data/` خرجتا عن التزامن

**العرَض:** صفحة لمقال محذوف ما زالت تُقدَّم، أو مقال موجود بلا صفحة، أو
خريطة الموقع تشير إلى ما لا وجود له.

الملفّات المولَّدة **مشتقّة بالكامل** من `data/` — فأعد اشتقاقها من الصفر:

```bash
rm -rf articles projects topics a p assets/og
npm run seo
```

الكنس والبناء معاً يعيدان الحالة الصحيحة تماماً. `data/articles.json`
و`data/projects.json` لا تُمسّان (يكتبهما جالبا Notion وحدهما)، و
`data/slugs.json` يُدمَج فلا تضيع المعرّفات.

**إن كان `data/` نفسه هو الخاطئ** (مزامنة أنتجت ملفاً ناقصاً):

```bash
git checkout HEAD~1 -- data/articles.json data/projects.json
npm run seo
```
ثم شغّل المزامنة من GitHub → Actions.

**كيف تتأكّد:**

```bash
npm run check                                    # يجب أن يمرّ بلا أخطاء
node -e "const s=require('fs').readFileSync('sitemap.xml','utf8');
  console.log((s.match(/<loc>/g)||[]).length, 'رابطاً')"
```

عدد الروابط يساوي: ٤ صفحات ثابتة + عدد المقالات + عدد المشاريع + عدد
الموضوعات.

### د. تأكّد أن الموقع الحيّ عاد فعلاً — لا «انظر إليه»

فحص واحد يغطّي الطبقات كلها:

```bash
for U in "/" "/articles/" "/projects/" "/topics/" "/sitemap.xml" "/feed.xml" "/robots.txt"; do
  printf "%-14s %s\n" "$U" "$(curl -s -o /dev/null -w '%{http_code}' "https://alzobaidi.me$U?cb=$RANDOM")"
done
```

**المتوقّع: `200` في كل سطر.** ثم تأكّد أن المحتوى حاضر بلا جافاسكربت —
وهو جوهر هذا الخطّ كلّه:

```bash
curl -s "https://alzobaidi.me/articles/?cb=$RANDOM" | grep -c "article-card\|article-lead"
```

يجب أن يعطي رقماً **أكبر من صفر**. إن أعطى صفراً فالتصيير المسبق لم يصل،
مهما بدت الصفحة سليمة في المتصفّح (جافاسكربت تملؤها عندك ولا تملؤها للزاحف).

## ١٢. حين يعطب شيء

| العرَض | السبب الأرجح | العلاج |
|---|---|---|
| البناء يقول «علامة المنطقة المُدارة مفقودة» | حُذفت علامة `seo:` من `index.html` | أعد الملف من git أو أعد العلامتين |
| «تعذّر تحميل أدوات توليد بطاقات المشاركة» | `npm install` لم يُشغَّل | `npm install` |
| الفاحص: «عنوانان متطابقان» | مقالان بالعنوان نفسه في Notion | غيّر أحدهما |
| الفاحص: «صفحة يتيمة» | موضوع لا يشير إليه أي محتوى | تحقّق من الوسوم |
| الفاحص: «باعث التحديث غير موحّد» | رُفع في `site.json` ولم يُرفع في `index.html`/`404.html` | ارفعه فيهما |
| صفحة قديمة ما زالت تُقدَّم بعد حذف المقال | البناء لم يُشغَّل بعد الحذف | `npm run build` (الكنس يزيلها) |
| تصادم معرّفات | عنوانان يعطيان نفس المعرّف | البناء يضيف لاحقة `-2` تلقائياً؛ غيّر أحد العنوانين لمسار أجمل |
| أردت اختبار انقسام خريطة الموقع | الحدّ ٥٠٠٠ ولن يُبلَغ قريباً | `SITEMAP_MAX=5 npm run seo` ثم `npm run seo` لإعادته |

## ١٣. ما لا يفعله هذا الخطّ

- **لا يترجم.** مبدّل EN في الترويسة يبدّل نصوص الواجهة في المتصفّح فقط؛
  لا توجد صفحات إنجليزية ولا روابط `hreflang` — وإضافتها بلا صفحات حقيقية
  تصريحٌ كاذب لمحرّك البحث. التفصيل في `SEO-REPORT.md` §٥.
- **لا يكتب محتوى.** لا وصفاً ولا نصّاً بديلاً ولا حقلاً في البيانات المنظّمة
  لا أصل له في `data/`.
- **لا ينشر.** الإيداع والدفع من عمل GitHub Actions أو منك.
