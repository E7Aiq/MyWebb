# الاشتراك بالبريد — كيف يعمل، وما الذي عليك فعله

نظام اشتراك بقائمتين: **ذُرى** (مشاريع) و**بان** (مقالات). المشترك يختار
واحدة أو الاثنتين، ويصله بريد واحد حين يُنشر جديد في ما اختاره.

---

## ١. لماذا المفتاح في المستودع — وليس تسرّباً

**اقرأ هذا القسم كاملاً قبل أن تقلق من رؤية مفتاح في `data/site.json`.**

لـSupabase مفتاحان مختلفان اختلافاً جوهرياً:

| المفتاح | ماذا يفعل | أين يسكن |
|---|---|---|
| **`anon`** (العامّ) | يُعرّف المشروع فقط. صلاحياته **ما تمنحه إيّاه قاعدة البيانات ولا شيء غيره** | `data/site.json` — **منشور عمداً** |
| **`service_role`** (السرّي) | يتجاوز كل السياسات. مفتاح كامل الصلاحية | GitHub Secrets **وحدها** |
| **`sbp_…`** (رمز الإدارة) | يتحكّم بحسابك كلّه، لا بهذا المشروع وحده | **لا مكان له في التشغيل إطلاقاً** |

الموقع ساكن على GitHub Pages: لا خادم، ولا مكان يُخفى فيه شيء عن المتصفّح.
أي مفتاح يحتاجه نموذج الاشتراك **سيصل المتصفّح حتماً** — ومن يفتح «عرض
المصدر» يراه. هذه ليست ثغرة في التصميم، بل طبيعة المواقع الساكنة.

**ولذلك الأمان ليس في الإخفاء، بل في أن المفتاح لا يمنح شيئاً:**

```
GET  /rest/v1/subscribers   →  42501 permission denied
POST /rest/v1/subscribers   →  42501 permission denied
```

الجدول **محجوب تماماً**: لا قراءة ولا كتابة مباشرة. كل ما يستطيعه حامل
المفتاح العامّ استدعاء دالّتين محكومتين (`subscribe` و`unsubscribe`)
تتحقّقان من مدخلاتهما ولا تُرجعان بيانات أحد. **لا يمكن سحب قائمة
المشتركين، ولا معرفة إن كان بريد بعينه مشتركاً.**

> **ما يجب أن يبقى سرّاً فعلاً:** `service_role` ورمز الإدارة `sbp_`.
> هذان لا يظهران في أي ملف بالمستودع، والفاحص أدناه يمنع دخولهما.

## ٢. البنية

```
المتصفّح ──rpc/subscribe──►  Supabase (RLS مقفلة)
                                  │
GitHub Actions ──service_role──►  يقرأ المشتركين
                                  │
                                  └──► Resend ──► بريد المشترك
```

| الملف | دوره |
|---|---|
| `css/subscribe.css` | البطاقة والمفتاح الانزلاقي |
| `js/subscribe.js` | فتح اللوح والإرسال |
| `js/unsubscribe.js` | صفحة `/unsubscribe/` |
| `.github/scripts/notify.js` | يرسل عند الجديد |
| `data/site.json` ← `subscribe` | الأصل والمفتاح العامّ |

**الجداول:** `subscribers` (بريد · ذُرى · بان · رمز إلغاء) و`sent_log`
(ما أُرسل، بمفتاح مركّب يمنع التكرار).

## ٣. السلوك الذي قد يفاجئك

**الاشتراك يدمج ولا يستبدل.** من اشترك في ذُرى ثم اشترك في بان من صفحتها،
يبقى في الاثنتين. النموذج لا يُلغي اشتراكاً قائماً أبداً — الإلغاء يقع من
رابط البريد وحده. بغير ذلك كان المشترك يخسر قائمةً بلا أن يقصد.

**إلغاء كل القوائم يحذف الصفّ.** لا نحتفظ ببريد لا نستعمله.

**أوّل تشغيلة تختم ولا ترسل.** لو وجد `notify.js` سجلّ الإرسال فارغاً، ختم
كل المحتوى القائم «أُرسل» بلا إرسال. بغير ذلك كان أوّل مشترك يستقبل أرشيف
الموقع كلّه دفعةً واحدة.

**الاشتراك أحاديّ التأكيد.** من يكتب بريده يُدرَج فوراً بلا رسالة تأكيد،
ومعه رابط إلغاء في كل بريد. لتفعيل التأكيد المزدوج لاحقاً: اجعل
`confirmed` افتراضه `false`، وأرسل رسالة تأكيد، واجعل `notify.js` يقرأ
`confirmed=is.true`.

## ٤. ما عليك فعله — ثلاث مهامّ

### المهمّة أ — دوّر رمز الإدارة (عاجلة، ٣ دقائق)

الرمز في `env.MyWeb_Supbase.rtf` على سطح مكتبك هو **رمز وصول شخصي كامل
الصلاحية على حسابك كلّه** — لا على هذا المشروع وحده. استعملتُه لإعداد
قاعدة البيانات، وقد مرّ في نصّ هذه المحادثة.

1. افتح `https://supabase.com/dashboard/account/tokens`
2. جِد الرمز المستعمل واضغط **Revoke**.
3. لا تحتاج بديلاً: التشغيل اليومي **لا يستعمل هذا الرمز إطلاقاً**، وإنما
   `service_role` وحده.
4. احذف ملف `env.MyWeb_Supbase.rtf` من سطح المكتب، أو انقله إلى مدير كلمات
   مرور.

**كيف تتأكّد:** أعد فتح صفحة الرموز — يجب ألّا يظهر.

---

### المهمّة ب — أنشئ حساب Resend واربط نطاقك (١٥ دقيقة)

**لا يمكن أتمتتها:** تحتاج إنشاء حساب باسمك، وإضافة سجلّات DNS عند مسجّل
نطاقك. لا أملك ولا يجوز أن أملك أياً منهما.

**لماذا Resend:** ٣٠٠٠ رسالة شهرياً مجاناً، وربط النطاق فيه أبسط ما وجدت.
أي مزوّد آخر يعمل — غيّر دالّة `send()` في `notify.js`.

1. افتح `https://resend.com` ← **Sign up**.
2. من القائمة الجانبية: **Domains** ← **Add Domain**.
3. اكتب `alzobaidi.me` ← **Add**.
4. ستظهر ثلاثة سجلّات DNS (‏`MX` و`TXT` لـSPF و`TXT` لـDKIM). افتح لوحة
   مسجّل نطاقك وأضفها كما هي حرفاً بحرف.
5. ارجع إلى Resend واضغط **Verify**. قد يستغرق الانتشار حتى ساعة.
6. بعد ظهور **Verified**: **API Keys** ← **Create API Key** ← الاسم
   `alzobaidi-site` ← الصلاحية **Sending access** ← **Create**.
7. **انسخ المفتاح الآن** — لا يُعرض مرّة أخرى.

**كيف تتأكّد:** حالة النطاق **Verified** بعلامة خضراء.

---

### المهمّة ج — أضف الأسرار الأربعة في GitHub (٥ دقائق)

**لا يمكن أتمتتها:** تحتاج صلاحية مالك المستودع.

1. افتح `https://github.com/E7Aiq/MyWebb/settings/secrets/actions`
2. **New repository secret** لكل واحد من الأربعة:

| الاسم | القيمة |
|---|---|
| `SUPABASE_URL` | `https://hswidotyrnlvkkeddszn.supabase.co` |
| `SUPABASE_SERVICE_KEY` | من `https://supabase.com/dashboard/project/hswidotyrnlvkkeddszn/settings/api-keys` ← انسخ **`service_role`** (لا `anon`) |
| `RESEND_API_KEY` | المفتاح من المهمّة ب |
| `MAIL_FROM` | `بان وذُرى <hello@alzobaidi.me>` — والبريد **يجب** أن يكون على النطاق الموثَّق |

**كيف تتأكّد:** GitHub ← Actions ← **Update Articles from Notion** ←
Run workflow. افتح السجلّ وانظر خطوة **Notify subscribers**:

- «📭 الإشعار البريدي غير مهيّأ» ⇒ سرٌّ ناقص أو اسمه مختلف.
- «✅ لا جديد يستحقّ الإرسال» ⇒ **كل شيء يعمل** (لا جديد بعد).

## ٥. اختبار الحلقة كاملة

1. اشترك ببريدك من `/articles/`.
2. في Notion: أنشئ مقالاً، أشّر **Published**، واملأ **Tags**.
3. Actions ← Update Articles from Notion ← Run workflow.
4. يصلك البريد خلال دقيقة من انتهاء التشغيلة.
5. اضغط **إلغاء الاشتراك** في ذيل البريد وتأكّد أنه يعمل.

## ٦. مراجعة المشتركين

لا توجد لوحة في الموقع — عمداً: صفحة تعرض المشتركين تحتاج تسجيل دخول،
وتسجيل الدخول سطح هجوم لا داعي له في موقع ساكن.

`https://supabase.com/dashboard/project/hswidotyrnlvkkeddszn/editor`
← جدول `subscribers`.

عدد المشتركين في كل قائمة:

```sql
select
  count(*) filter (where dhura) as ذرى,
  count(*) filter (where ban)   as بان,
  count(*)                      as الكل
from subscribers;
```

## ٧. إن تعطّل شيء

| العرَض | السبب الأرجح | الإصلاح |
|---|---|---|
| «تعذّر إتمام الاشتراك» في المتصفّح | المشروع موقوف (يتوقّف بعد خمول) | افتح لوحة Supabase واضغط **Restore** |
| البريد لا يصل | النطاق غير موثّق في Resend | أكمل المهمّة ب |
| «📭 غير مهيّأ» في السجلّ | سرٌّ ناقص | المهمّة ج |
| بريد مكرّر | صفٌّ حُذف من `sent_log` | لا تحذف منه يدوياً |
| أرشيف كامل وصل مشتركاً | `sent_log` أُفرغ | أعد ختمه: شغّل `notify.js` والسجلّ فارغ فيختم بلا إرسال |

**التوقّف عن الخمول:** المشاريع المجانية تتوقّف بعد أسبوع بلا طلبات. زيارة
واحدة لصفحة فيها نموذج الاشتراك تكفي لإبقائه حيّاً، لكن لا تعوّل على ذلك —
إن كانت القائمة تهمّك فالخطّة المدفوعة تزيل المسألة.
